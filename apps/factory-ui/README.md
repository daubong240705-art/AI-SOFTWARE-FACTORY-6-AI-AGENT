# Factory UI (V2)

Vite 8 + React 19 + TypeScript. Talks only to the Host HTTP API; independent of V1.

```sh
cd apps/factory-ui
npm ci --ignore-scripts --no-audit --no-fund
npm run check     # tsc --noEmit
npm run build     # -> dist/, served by the Host (FACTORY_UI_DIR or ../factory-ui/dist)
npm run dev       # Vite on 127.0.0.1:5173, /api proxied to the Host (FACTORY_PORT, default 8787)
```

## Core (no screens yet)

- `src/api/client.ts`: every Host response is validated with the `@factory/contracts` schemas before use; error messages are fixed strings (never server text, tokens or cookies); the CSRF header is sent only on POSTs; the bootstrap token is only ever in the JSON body of `POST /auth/bootstrap`.
- `src/api/commands.ts`: builders that return valid commands; re-sending the same command object keeps its `commandId` (idempotent retry).
- `src/api/events.ts`: Server-Sent Events with schema validation; the browser resumes with `Last-Event-ID` by itself; `snapshot-required` closes the stream and asks for a full refresh.
- `src/state/store.ts`: small external store, debounced and non-overlapping refetches, stale responses discarded when the selection changes, 401 resets the session.
- `src/i18n`: labels come from `design/factory-v2/labels.{en,vi}.json` plus `extra.{en,vi}.ts`; default locale `en`; theme `light | dark | system`.
- `scripts/build-tokens.mjs`: generates `src/styles/tokens.css` and `public/fonts/` from `design/factory-v2` (git-ignored, regenerated by `predev`, `prebuild`).

## Board and task detail

Tasks open in a Board by default; Board/List preferences last only for the store's lifetime. The Board groups tasks by lifecycle and actionable holds. Cards open a responsive task dialog with request, attempts/progress, results, and confirmed Start/Stop/Retry actions. Conflict retries reload revisions before confirmation.

Server text is always rendered as React text, including markdown artifacts and patch lines. No HTML or markdown is evaluated. Diff previews are bounded, expand on demand, and retain non-colour addition/removal cues. Patches can be copied or downloaded; unavailable browser APIs show manual fallback instructions.

The store exposes `openTask(taskId)`, `closeTask(taskId)`, `loadTaskDetail(taskId)`, `loadAttemptEvents(taskId, attemptId)`, `loadPatch(taskId, attemptId)` and `loadArtifactContent(taskId, artifactId, version)`. `details` contains attempts, paged events (up to 2,000 per attempt), artifacts, approvals and patches. `artifactContents` and patches share a 20-entry memory cache. SSE changes refresh open details through the existing debounced queue; project/session changes discard stale reads and clear detail data. Approval decisions and Inbox UI are reserved for the next slice.
### Inbox, decisions, and publishing branches

The topbar Inbox collects pending reviews, questions, and start gates across projects. The project Inbox tab shows the selected project's items. Badges refresh after commands, on project events, on focus, and every minute while the tab is visible.

Reviews and questions load the current approval before a decision. Options show their consequences and require confirmation; requesting review changes requires a comment. Changed or expired approvals must be reviewed again. Task Results and Actions show pending decisions and their history. All Host content is rendered as plain text.

Push appears only for done tasks with a `factory/` workspace branch and configured remote names. Confirmation publishes that branch outside Factory, never forces, and never touches main. Unknown results require explicit reconciliation against the remote; the UI never retries automatically. Failed pushes may be requested again. Remote URLs are never requested or displayed. Git projects use an existing clone under the Host's projects root; see the runbook for clone setup.

## Knowledge tab

Knowledge searches documents (including Vietnamese with or without accents), browses filtered artifacts, and shows versions and provenance. Search waits 300 ms; collections page up to 500 rows. Artifact events refresh open views only. Project changes and session loss clear knowledge state and discard obsolete responses.

This tab is read-only. Responses use strict field, enum, size, and array validation; errors use fixed translated categories. Titles, summaries, snippets, provenance and content are React plain text, never HTML or markdown. Text previews stop at 20,000 characters with a visible note. Data stays in memory, using the existing bounded content cache. Status and visibility have visible text labels. Details use the shared focus-trapping dialog, presented as a side panel on wide screens and full screen on phones.
