## Behavior

Default remains sequential, including old saved settings. Opt in under Settings → Team execution. The Lead plan remains dependency ordered. Isolated mode selects at most two queued root work tasks with disjoint case-insensitive scopes. Git workspace mutations serialize; runtime execution overlaps. Roots with overlapping scopes run in separate batches. Declared scope is a scheduling/permission policy, not an OS filesystem sandbox.

Every task receives a locked detached worktree from the same clean original baseline. Original source/index are not merged or committed. Changing original source, task ownership or task HEAD blocks further progress and retains files. Dependencies never consume another worktree implicitly. Completed root results stop at integration-pending, even if all root-local checks pass. A no-work conversational Lead reply still completes normally.

Requests are reserved synchronously across proxies and never refunded. The deadline is run-wide. Stop closes admission, closes all proxies/process jobs and waits for containment. Failure to confirm termination holds the run lock for explicit retry. Failures stop sibling runtimes; no later batch starts. Worktrees remain registered and owned after cancellation/restart; history references prevent cleanup while retained.
