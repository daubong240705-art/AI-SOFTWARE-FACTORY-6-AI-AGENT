Mốc tiếp theo đã bổ sung deploy boundary kiểm tra approval/artifact/health, live TEST fail → Bug → một vòng sửa → TEST pass, recovery lease và systemd restart, webhook HTTPS/replay, backup/restore schema0004 ở DB riêng. Chi tiết và giới hạn ở [staging](phase-5-staging.md), [evidence](phase-5-staging-evidence.json). Bộ backend hiện có **54 test đạt**; kết quả trong các mục smoke dưới đây là lịch sử của mốc đầu tiên.

## Việc phải hoàn tất trước nghiệm thu v0.2

1. Staging tổng hợp đã có deploy boundary kiểm tra approval/SHA/ref/artifact/health. Tiếp tục nghiệm thu rollback container và cấu hình policy cho từng sản phẩm thực; xem mốc staging riêng.
2. Live test-fail → Bug → sửa giới hạn → pass, lease recovery, systemd restart và webhook HTTPS đã có evidence ở mốc staging. Còn browser/BFF và reboot/worker máy cá nhân; không suy rộng evidence sang các môi trường chưa chạy.
3. Đã thêm proxy theo execution: giới hạn request vật lý, output, ngân sách và không truyền API key thật vào sandbox. BE/FE đã smoke qua proxy với 4/7 request; xem [runtime](agent-runtime.md). Trần hóa đơn hoặc hành vi retry bên trong gateway chưa được bảo đảm; chưa báo cost tiền hay upstream model mà gateway không trả về.
4. Mốc staging đã khóa job/pipeline/ref, kiểm tra CI/package script và source artifact độc lập tại host, kiểm tra approval lưu DB và HTTPS health sau job success. Tiếp tục rà soát policy riêng từng project. Worker là máy quản trị tin cậy; credential worker bị lộ có thể báo cáo giả kết quả local test. Cần quản trị thiết bị/rotation theo mức tin cậy này.
5. Đã có UI quản lý worker, heartbeat/offline, đăng ký/rotate/revoke token và catalog kỹ năng/model. Probe model từ parent đã đạt tìm/đọc/sửa/test thật và chặn quota; dashboard chưa tự chạy probe. Node profile, worker máy cá nhân Linux/WSL2 và reboot systemd cần smoke riêng. Cá nhân dùng cùng protocol outbound; chưa nghiệm thu trực tiếp thiết bị cá nhân.
6. Rà soát migration/rollback trước deploy `.14`. Schema mới additive `0004_agents`; v0.1 cũ readiness yêu cầu đúng `0003_auth`, nên không coi rollback image cũ là đủ. Cần compatibility release chấp nhận additive schema mới **hoặc** quy trình restore có maintenance window được kiểm chứng. Không downgrade live DB. Release manifest đã ghi `0004_agents`; wrapper mặc định policy `0003_auth` sẽ từ chối cho đến khi host admin cập nhật policy sau review. Chưa thay policy/wrapper/runtime production.
7. Chạy lại full live chain trên image của commit cuối, CI release và browser gate/execution; backup/restore schema mới ở môi trường tạm. Sau đó mới bật profile staging và nghiệm thu Phase 5. Phase 6 tiếp tục template/Mini Helpdesk/benchmark.

## Cấu hình dành cho vận hành

`ASF_MODEL_CATALOG` là JSON array; mặc định `coding-main` phải nằm trong catalog. `ASF_INTEGRATION_PROFILES_FILE` trỏ file JSON root-owned, mount read-only vào API và workflow worker. Ví dụ [profile](../../../infrastructure/worker/integration-profiles.example.json) mặc định disabled. `ASF_GITLAB_API_TOKEN`/`ASF_OPENPROJECT_API_TOKEN` là bot hạn quyền, server-side, không dùng PAT bootstrap admin. Model key vẫn chỉ ở workflow/coding worker; API không nhận model key. API cần egress và CA để gọi GitLab/OpenProject; Compose production Phase4 chưa nối cấu hình này.

Trang `/admin/agents` hoặc `POST /api/coding-workers` bằng session admin + CSRF trả token **một lần**, gửi qua kênh riêng; `DELETE /api/coding-workers/{id}` revoke. Worker đặt token trong file root600 ngoài repo theo [env example](../../../infrastructure/worker/agent.env.example). [systemd unit](../../../infrastructure/worker/asf-coding-worker.service) là mẫu chưa enable. Parent cần Linux, Docker và Python environment có httpx; coding image phải build từ worker Dockerfile và hiện diện trước (`--pull=never`). Không mount Docker socket vào coding/test container; không cấp GitLab/admin/deploy token cho CLI.

Source/evidence dev trên `.60:/srv/asf-phase5`, secret tại `private/` root700/file600. API thử nghiệm của mốc đầu chỉ bind loopback `18450`. Mốc staging mới dùng Caddy `/phase5-api/` và API `.60:18050` với firewall chỉ cho nguồn `.51`; xem tài liệu staging. Không thay route dashboard/API production. DB/Redis thử nghiệm dùng loopback 54339/56389; DB live smoke `asf`, DB test riêng `asf_tests`. Không chạy test vào DB smoke đang có run active: unique active-run sẽ từ chối, đúng thiết kế. Tất cả tách production/legacy; hai container ITCare được giữ dừng theo yêu cầu.
